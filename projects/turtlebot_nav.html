04Why Jazzy Instead of Humble — And What It Costs

Humble is the more established LTS release. Choosing Jazzy instead means learning to diagnose and adapt in an ecosystem mid-transition — itself part of the learning goal.

Gazebo Harmonic's install & bridging setup differs from Classic
Harmonic is a new architecture, not an incremental update — install steps and the ROS–Gazebo bridge configuration don't match older Classic-based tutorials.
TurtleBot3 packages must be compiled from source
Jazzy binaries for TurtleBot3 aren't fully published yet, so the core packages need to be built from source rather than installed via apt.
/cmd_vel now defaults to a stamped message type
A breaking change from earlier distributions — velocity command messages now default to the stamped variant, which trips up drive code written against older examples.

05Future Work — Extending the Project

Once the core perceive-plan-act loop and vision layer are working, these are natural directions to take it further.

Sim-to-real transfer
Port the working stack onto a physical TurtleBot3 Waffle Pi, dealing with real sensor noise, calibration, and network setup that simulation hides.
Deep-learning object detection
Replace the color-threshold detector with a lightweight model (e.g. YOLO) for robust, class-based object recognition instead of hue matching.
Dynamic obstacle avoidance
Add moving obstacles to the simulated world and extend Nav2's costmaps for reactive replanning around them in real time.
Multi-robot coordination
Spawn a second TurtleBot3 in the same world and explore namespacing, shared maps, and basic fleet coordination.
Voice / natural-language commands
Add a speech-to-text front end that turns spoken commands into Nav2 goal poses or vision-target requests.
Autonomous docking & recharge behavior
Design a docking behavior tree in Nav2 that returns the robot to a charging station once a task or battery threshold is reached.
Remote monitoring dashboard
Build a web dashboard (rosbridge or Foxglove) to view the live map, camera feed, and robot state from another device.
Migration notes: Jazzy → Humble/LTS
Document the reverse porting path, capturing which workarounds (source builds, message-type fixes) become unnecessary on an LTS release.
Takeaway: the goal isn't just following a working tutorial to a green checkmark — it's building the diagnostic muscle to adapt when the tools underneath you are still shifting.
